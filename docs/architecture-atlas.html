      Component directory

      ComponentStageResponsibility
      Action proposalAdmissionAn immutable description binds the target, parameters, evidence plan and expiry to one digest.
      Policy decisionAdmissionThe caller supplies a decision and its policy digest. The reference sidecar accepts this input for its synthetic connector.
      Recourse reservationAdmissionThe connector signs a commitment covering a bounded remedy for the exact action. The rail checks its status again before use.
      Recovery drillRecoveryWhere policy requires preflight, an isolated fixture supplies a signed drill bundle. The rail checks its bindings, qualification and freshness.
      Action permitAdmissionThe rail issues a single-use permit after the required gates pass. The permit expires and binds the action and reservation.
      Connector executionSettlementThe protected connector consumes the authorized operation. Ambiguous execution is reconciled through status before proceeding.
      Outcome evidenceSettlementThe rail checks the source, resource and freshness of the observed state and evaluates the declared postcondition.
      Settlement receiptSettlementClosing binds a technical outcome to the signed event chain. A verified remedy can yield compensation. An unresolved result may be disputed.
      Offline verificationReviewCaller-selected trusted keys check artifact integrity. An audit bundle also supports replay of the lifecycle and its evidence.
      Directed connections
      • Action proposal binds authorization to the action → Policy decision.
      • Policy decision allows a reservation request → Recourse reservation.
      • Recourse reservation binds a verified commitment → Action permit.
      • Recourse reservation defines the drill envelope → Recovery drill.
      • Recovery drill qualifies required preflight → Action permit.
      • Action permit authorizes one attempt → Connector execution.
      • Connector execution produces an observable effect → Outcome evidence.
      • Outcome evidence supports the terminal outcome → Settlement receipt.
      • Settlement receipt is checked within a saved bundle → Offline verification.
